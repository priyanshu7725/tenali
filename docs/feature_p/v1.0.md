- **Target SRS ID**: `Feature P`
- **Author**: Priyanshu Kumar (@priyanshu7725)

## Feature Description
This feature introduces an active safety routing engine to implement mastery learning. Instead of permitting students to fail repeatedly or artificially reducing problem difficulty, the system identifies when a student is struggling. It intercepts the active quiz, identifies likely prerequisite concepts that may be contributing to the student's difficulty, and routes the student to a quick, targeted warmup on that prerequisite before seamlessly returning them to the original workflow.

## Final Architecture (v1.0)
- **Direct Prerequisite Lookup**: Fetches prerequisite dependencies directly from the server adjacency list configuration (`prerequisites.json`) via dynamic endpoint lookups.
- **Student-Controlled Prerequisite Selection**: Employs the Prerequisite Picker UI modal, letting users select a supported prerequisite or continue with their active task.
- **Warmup Compatibility Whitelist**: Ensures fetched prerequisite topics pass compatibility checks (single text/numeric input and matching `/check` structure). Uses `getWarmupPrompt` to normalize diverse question shapes.
- **Progressive Intervention**: Escalates struggle triggers progressively (Auto-Warmup → Prerequisite Picker → Learning Recommendation).
- **State Preservation and Seamless Return**: Preserves quiz context (`frozenQuizState`), restores state cleanly, and triggers dual cooldown filters (`cooldownRef = 4`, `hesitationCooldownRef = 2`) to ensure smooth return paths.

## Technical Evolution
### v0.1
- Sliding-window struggle detection (3 incorrect out of 4)
- State preservation and snapshotting
- Hardcoded warmups (addition prototype)
- Baseline 4-question cooldown

### v0.2
- Dynamic prerequisite resolution (`GET /api/prerequisites/:topic`)
- Compatibility whitelist (`WARMUP_SUPPORTED_TOPICS`)
- Session history guard (`sessionWarmupTopicsRef`)
- Recursive BFS traversal (caching, cycle detection, and max depth limits)
- Prompt normalization layer (`getWarmupPrompt`)

### v0.3
- Three-tier escalation (Auto-Warmup → Prerequisite Picker → Learning Recommendation)
- Student-controlled prerequisite picker modal
- Learning Recommendation panel
- Hesitation Monitor integration
- Removal of recursive prerequisite traversal
- Dual cooldowns (`cooldownRef` and `hesitationCooldownRef`)
- Telemetry cleanup

## Final Design Philosophy
Feature P evolved from an automatic prerequisite routing system into a student-guided intervention framework. Rather than assuming the system can precisely infer a student's knowledge gap, the final design combines automated struggle detection with student choice, allowing learners to decide which prerequisite concept they wish to review while preserving quiz progress and minimizing frustration.

## Acceptance Criteria
- Sliding window correctly flags poor performance (3/4 wrong).
- Picker options correctly disable unsupported formats with a `[Warmup unavailable]` tag.
- Completed topics remain selectable to permit student optional practice.
- Completed warmups bypass struggle-trigger loops for subsequent questions via cooldown guards.
- The system avoids repeatedly recommending the same prerequisite warmup within a single quiz session.
- Database starts without connection crashes.

## Appendix: Implementation Notes
- **Local DB Connection Timeout**: During integration testing, we resolved a startup database connection crash by increasing Mongoose `serverSelectionTimeoutMS` from 4000 to 10000 inside `server/auth.js`. This prevents connection timeouts caused by the synchronous `bcryptjs` password hashing routine blocking the Node.js event loop during startup.
